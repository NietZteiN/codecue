\title{Computed but Not Written: Where a Misleading Identifier Enters a Code Trace}

\author{Anonymous ACL submission}

\begin{document}
\maketitle

\begin{abstract}
Misleading identifiers lower the accuracy of language models on code, and step-by-step
reasoning does not restore it. We ask where the identifier enters. We construct a cue-conflict
version of output prediction: short Python functions in which one identifier implies an
executable value different from the one the code computes, rendered with congruent, neutral and
misleading names on matched twins, and traced line by line by \NUM{n-models} instruction-tuned
models with three sets of worked examples. When a variable computed as \texttt{len(xs)} carries
a sum-like name, general models write the sum at that step \NUM{cell-llama8-excess} to
\NUM{cell-olmo7-excess} points above the twin's rate, and a code model does the same on
\texttt{max(xs)}. At the token where the model writes that step, linear probes read the code's value in
\NUM{probe-olmo7-code}--\NUM{probe-llama8-code}\% of these instances and the name's value in
\NUM{probe-olmo7-name}\%. Activation patching places the origin of the effect at the name's
tokens and shows it arriving at the writing position in the middle of the network, where
replacing a single layer removes it. Writing the expression beside the value in the worked
examples also removes it. The effect is several times weaker in a REPL transcript, reduced to
a residue at 34B parameters, and not detectable on renamed CRUXEval functions.
\end{abstract}

\section{Introduction}

Consider the function in Figure~\ref{fig:idea}(a). The variable \texttt{sum\_all} is assigned
\texttt{len(xs)}, so on the input \texttt{[5, 3]} it holds 2 and the call returns 9. The name
says that it holds \texttt{sum(xs)}, which would be 8 and would make the call return 15. Both
readings are executable, and only one is the code. We call 8 the \emph{lure value} of the name
and 2 its \emph{true value}. If a model writes 8 for that step, or 15 as the answer, the meaning
of the name has reached the computation.

\paragraph{Motivation.} Identifiers that contradict the code they name reduce model accuracy on
code comprehension \cite{le2025names,lam2025codecrash}, and \citet{le2026obfuscated} report
that the loss is largest for the strongest code models and is not removed by step-by-step
reasoning. A drop in accuracy does not say where the name interferes: the input may be misread,
the computation may be corrupted, or a correct computation may be misread at the output.
\citet{kudo2026faithful} locate, with probes and patching on arithmetic, the point in a chain of
thought at which each intermediate value becomes decodable, and \citet{anon2026arith} add a
cue conflict to that setting and find that a written chain removes the influence of a
misleading variable name wherever the value is represented. Code traces differ from arithmetic chains in one respect: a trace writes a variable's value
without restating the expression that produced it. We find that this is where the name enters.

\paragraph{This paper.} We place two cues in conflict, as in the Stroop task \cite{stroop1935}
and the shape--texture experiments on vision models \cite{geirhos2019texture}, inside a
CRUXEval-style output-prediction task \cite{gu2024cruxeval} on synthetic Python. Each misleading name comes from a table of (name, operation) pairs, and the lure value is
obtained by executing the function with the implied operation in place of the real one, so the
lure is itself a program. Matched twins differ in a single identifier, so every number below is an excess over the neutral
twin. The name's influence is confined to one kind of step, one kind of name and one kind of format,
and we locate it: the value is computed and decodable where the model writes the
step, the name's tokens are the causal origin, and the output head writes the name's value anyway.

\section{Setup}

\paragraph{Task.} A problem is a Python function of one list argument, a chain of one to three
assignments, a return, and a call on a short list of distinct digits. The first assignment
applies a list aggregate (\texttt{len}, \texttt{sum}, \texttt{max}, \texttt{min}); later ones
apply a unary or binary integer operation. Every intermediate and final value is a single digit,
as in \citet{kudo2026faithful}, so probes are 10-way classifiers. Table~\ref{tab:levels} in the
appendix lists the levels. Our main level has three assignments (level~5); the one-aggregate
level (3) is reported in the appendix.

\paragraph{Naming conditions.} Each problem is generated once and rendered with different names
for one variable, the \emph{target}: a \emph{congruent} name whose implied operation is the
code's own, a \emph{neutral} name of one or two letters, and a \emph{misleading} name whose
implied operation differs. Names come from a fixed table of \NUM{gate-names} identifiers in
eleven families (\texttt{count}, \texttt{n\_items}, \texttt{length} for \texttt{len};
\texttt{total}, \texttt{sum\_all}, \texttt{acc} for \texttt{sum}; and so on; Table~\ref{tab:gate}).
The lure value is computed by execution and must differ from the true value and from every
other value in the program and its input, so a lure answer cannot be correct for another
reason and cannot be copied from the prompt. This last rule removes \texttt{max} and
\texttt{min} names as lures on a list-defined variable, since their implied value is an element
of the input. The testable misleading pairs on the aggregate step are therefore a
\texttt{len}-, \texttt{max}- or \texttt{min}-computed variable named like a sum, and a
\texttt{sum}-, \texttt{max}- or \texttt{min}-computed variable named like a length. A name is a
lure for a model only if that model reads it as the intended operation; a log-probability gate
records which operation each name evokes for each model (Appendix~\ref{app:gate}).

\paragraph{Formats.} In the \emph{direct} regime the model writes only the return value after
three worked examples. In the \emph{trace} regime the three examples trace the execution as
\texttt{qq = 3, v = 6, vv = 9} and then answer, and the model does the same for the problem.
Three further formats change only what a step looks like: \emph{trace-expr} writes
\texttt{qq = len(xs) = 3}; \emph{REPL} writes \texttt{>{}>{}>~qq} and then \texttt{3};
\emph{comment} rewrites the program with each value as an end-of-line comment. A \emph{prose}
regime asks the model to think step by step in its own words with no examples. Every few-shot
result is the mean over three fixed sets of worked examples.

\paragraph{Measures.} Our main measure is the \emph{written-lure excess}: the rate at which the trace's step for the
target states the lure value, minus the rate at which the neutral twin's step for the same
variable states that same number, so that an arbitrary wrong number counts in both. We count an effect as reliable when its sign is the same
under all three sets of worked examples and a cluster bootstrap over matched problems excludes
zero, and we treat effects inside two points as equivalent to zero.

\paragraph{Probes and patching.} A linear probe is trained on neutral problems only, one per
layer and position, to read the target's value from the residual stream, with the recipe and
hyperparameters of \citet{kudo2026faithful} and a control probe keyed on the name's identity
\cite{hewitt2019control}. We test it on misleading problems at the \emph{decision token}, the \texttt{=} after which the
trace writes the target's value, the first step of the trace. To test cause, we
replace the residual stream at one layer with the matched neutral twin's, either at every
token of the name or at the decision token, and read the digit the model writes
\cite{zhang2024patching}; a neutral-for-neutral replacement bounds the damage of any patch.

\paragraph{Models.} Seven instruction-tuned models (Table~\ref{tab:cells}) on every behavioural experiment, with
1{,}000 matched problems per cell and set of worked examples; CodeLlama-34B on the main level;
probes and patching on the first three.

\paragraph{Probes.} Probes trained on neutral traces and tested on the misleading
cell read the code's value at the decision token in \NUM{probe-olmo7-code}\%,
\NUM{probe-llama3-code}\% and \NUM{probe-llama8-code}\% of instances at the best layer, rising

\NUM{probe-olmo7-name}\% at any layer. The same models write the sum in

\paragraph{Patching.} Figure~\ref{fig:mechanism} shows the two patching sites, and
Table~\ref{tab:patch} in the appendix the layers. Replacing the name's tokens at layer 0 alone
removes \NUM{patch-olmo7-name-best}\% and \NUM{patch-llama3-name-best}\% of the lure writes
with no damage to correct instances, and the removal decays to nothing by the middle of the
network. Replacing the decision token alone removes nothing at the early layers and
\NUM{patch-olmo7-pre-all}--\NUM{patch-llama8-pre-all}\% from the middle of the network on.
The neutral-for-neutral control changes at most \NUM{patch-llama3-wordctl}\% of outputs at
either site. The two curves cross where the name's contribution has moved from its own tokens into the
decision token, where the probe reads the code's value at those same layers. The twin's vector
there also holds the code's value; substituting it removes the sum and nothing else.

\paragraph{Boundaries.} Three pre-registered tests bound the effect. On a level whose middle
step is a unary operation, no family of names moves that step for any model above the floor
(largest excess \NUM{l6-max-excess}). CodeLlama-34B traces the cell of Table~\ref{tab:cells}
with a written-lure excess of \NUM{cell34-len-excess} and the \texttt{max} cell with
\NUM{cell34-max-excess} [\NUM{cell34-max-lo}, \NUM{cell34-max-hi}], inside our equivalence
margin; we had predicted it to behave like CodeLlama-7B. On \NUM{crux-n} CRUXEval functions
that assign a length, a loop counter or a maximum, renamed by AST rewriting to \texttt{v} or
\texttt{total} and verified by execution, every interval for the paired misleading-minus-neutral accuracy
covers zero, and none extends beyond \NUM{crux-direct-bound} points in the direct regime or
\NUM{crux-prose-bound} points in prose (Table~\ref{tab:crux}). Natural code has no analogue of the trace format, so this bounds the regimes people use.

\section{Related Work}

\citet{kudo2026faithful} established when intermediate values are computed during arithmetic
chains, and \citet{anon2026arith} found the chain protective against a misleading name wherever
the value is represented; ours is the case in which the value is represented and the trace still
writes the name's. Misleading identifiers lower accuracy on real code
\cite{le2025names,lam2025codecrash,le2026obfuscated,orvalho2025mutations,gao2023cream} without
localisation inside the model. Chain faithfulness has been measured by perturbing prompts and
chains \cite{turpin2023unfaithful,lanham2023measuring,chen2025reasoning}; we measure it at the
token where the chain commits to a value. The Stroop design has been applied to next-token
prediction \cite{wang2026stroop,hu2026conflict}, not to a step inside a chain.

\section{Conclusion}

In a terse trace, small models write the value a sum-like name implies for a variable the code
computes otherwise, while the code's value is decodable at the token that writes the step. The
name's tokens are the origin, the decision token is where the influence acts, and one
replacement at either removes it, as does showing the expression beside the value. The effect
is largely confined to that format and to models of 8B parameters and below.

\section*{Limitations}

The programs are synthetic and short, with single-digit values, so the internal analysis has a
clean ground truth at the cost of realism; the renamed CRUXEval functions are the only natural
code, and only in regimes where the effect does not occur, with power to exclude effects above
about five points. The effect depends on the worked-example format, and the format that shows
it is one we constructed; the REPL and comment formats are closer to what people write and show
much less. The models are at most 34B, and the largest shows only a residue; two of four
pre-registered predictions about the boundaries were wrong, which we report as such. The
name-site patch cannot be applied to two-token names with token-aligned twins, so one model's
name-site result is missing. Probes read linearly decodable information only, and patching a
single position cannot exclude side effects, which is why a neutral-for-neutral control
accompanies every intervention. Models of Chinese origin were outside the scope of this study,
which leaves out the strongest open code models of \citet{le2026obfuscated}.

\section{Lure gate}
\label{app:gate}
 A name is a lure for a model only if that model reads it as the intended
operation. We score, for each model, the log-probability of each candidate right-hand side
after \texttt{def f(xs):\textbackslash n\ \ \ \ total =}, and record which operation each name
evokes (Table~\ref{tab:gate}). \NUM{gate-pass} of the \NUM{gate-names} names are read as
intended by at least 80\% of the models; most sum-family names are read as \texttt{len} rather than \texttt{sum} by
\NUM{gate-sum-len-readers} of the \NUM{n-models} models.
