# Computed-expression and late-reference discovery continuation

This continuation follows the digit-aligned literal assay. It has two separately identified datasets, configurations and runs. All outcomes are discovery data; no final/extrapolation outcomes, language-model training or new checkpoints are involved. The earlier arithmetic failures remain unchanged.

The computed-expression bank has 576 independently checked programs and 768 directed counterfactual pairs. It uses 12 disjoint numeric groups selected by a fixed hash order (seed 2026102604), two families, two ownership/overwrite mappings, two neutral lexical realizations, both queries and three numeric variants. Both values are produced by single additions. Every relevant base/donor result is absent from **all** literals in both programs. A donor changes just the first operand of one addition; the last operand token at its expression boundary is unchanged. Intervening there avoids directly replacing the changed input token, but could still transfer operand information for later recomputation rather than an abstract sum.

Before any computed-expression intervention, each complete family must reach at least 90% complete-answer accuracy, at most 5% invalid answers, and at least 24 examples in every mapping/query cell (the bank has 72 per cell). Families pass only if all four cells pass. Failed families retain every raw baseline and receive no interventions; successful individual cases are never selected to rescue a failed family. Both directions, both queries and all numeric/lexical variants remain in every eligible family. If neither family passes, this continuation reports baseline/gate results and makes no computed-transfer claim.

The late-reference bank contains 432 programs and 432 directed pairs. It reuses every 216 original ownership prompt as an exact anchor, adding a paired version where the final unused `buffer = 0` or `temp = 0` writes to `spare` instead. The complete prefix before that identifier, query values, literal exposure, statement counts and tokenizer lengths must match. Only that identifier token changes. Full final states and the number of distinct variable names differ, so this is a targeted dead-reference contrast, not a pure memory-load or lexical-cue isolation. The original discovery localized all 40 baseline errors to the second-variable query after a swap; this previously observed cell is nominated before the new run, alongside all unswapped and first-variable controls.

Late-reference interventions replace the changed assignment-identifier vector in both directions, without selecting correct or incorrect cases. The oracle answer never changes. The target log-odds contrast is correct digit versus the other binding's digit. Report patched and unpatched token accuracy together, full paired baseline flips, both donor directions and all four mapping/query cells. Correcting an already correct answer does not count as a repair effect. This tests a local contribution of an output-irrelevant reference, not a complete internal binding path or an explanation proven beyond this cohort.

Both assays reuse the pinned Llama 3.1 8B checkpoint, BF16 SDPA and the established `Output:\n ` prefix. Every greedy baseline must pass actual answer-digit alignment and prefill-logit/generation agreement. Actual-tokenizer QA precedes GPU inference. All source/configuration snapshots and semantic datasets are hashed. Same-batch direct-forward replays, fixed padding width and logical rotary positions make each destination vector auditable. Earlier captured vectors must be invariant across matched future queries. Unchanged anchor token IDs are checked explicitly.

At raw blocks 0, 8, 16, 24 and 31, retain primary transfer, norm-matched unrelated-position perturbation, answer-vector copying, identity sham and random directions with seeds 11, 29 and 47. Effective perturbation norms are matched after BF16 rounding within the fixed 3% tolerance. Final-block earlier-token controls must leave the answer unchanged, and final answer-vector controls must copy the donor digit. These are analytic software checks, independent of whether the primary intervention works. Full cohort results are primary; the original engine also records its both-baselines-correct descriptive subset. No layer is nominated as a confirmed mechanism.

The computed bank uses batch size 96 and the late-reference bank 144, both exact divisors of their baseline/pair counts, to improve GPU throughput over the earlier batch 48. Prior short-prompt BF16 measurements peaked near 16.2 GiB at batch 48; these short workloads remain eligible for A30/H100/H200. Actual memory, hardware and runtime are recorded. There is no project compute cap. The finite workloads are at most 26,880 computed-expression and 15,120 late-reference forwards. Only the scientific reliability gate may reduce the former. Independent jobs use available local GPUs; no paid infrastructure is provisioned.

Configurations: `configs/binding/competition/computed_routing_v1.json` and `swap_reset_v1.json`. The frozen source, jobs, complete audits and generated reports are under `artifacts/binding/routing_extension/` and `reports/binding/`. Numeric variants, fit directions and two lexical realizations are not independent structural replications. No population-level significance or confirmatory preregistration is claimed.

Tokenizer QA rejected `spare` before any reset-reference model inference: it adds a token in all 216 paired prompts. A CPU-only audit of the complete prompt selected `cache`, which preserves one-token contrasts in all 216 anchors. The corrected reset dataset/configuration and outputs use version 2; unqueried version 1 and its failed QA remain preserved. Exact original-anchor token identity and paired old/new baseline responses are recorded separately. The computed dataset and its passing QA remain version 1.
