# Local arithmetic dependencies: frozen discovery protocol

This follows the [probe improvement plan](arithmetic_probe_improvement_plan_v1.md). Original global-state results stay intact. This is an adaptive discovery study, not untouched confirmation or a causal intervention.

## Sources and behavioral calibration

Generate 288 new canonical structures: depths 2, 4 and 6 × addition/subtraction/mixed operators × 32 structures. Within each of the nine strata, 24 structures are TRAIN and eight are development, totaling 216/72. Exclude all 48 original canonical structures. Group every numeric and lexical relative with its structure. Three numeric seeds × uniform/equal-root/additive-root draws × two neutral lexical forms give 5,184 main prompts per model. An additional six canonical one-update structures, 108 prompts, are calibration only and never enter probe fitting or architecture selection. All initial states are distinct across numeric bodies; values are bounded by 96. Query selection balances computed and untouched variables when available; calibration always queries the updated variable. AST traces, ordinary Python assignment execution and renamed surface answers must agree.

Capture all 5,292 prompts per model under the original instruction. Separately generate answers for all 1,836 one/two-update prompts under all three fixed instructions: 5,508 answers per model, 11,016 total. Use explicit `print(variable)`, greedy BF16 inference, batch32, maximum12 tokens and the existing strict full signed-integer parser. Invalid responses remain wrong. Record counts, invalids and family-macro accuracy by instruction, split, depth and computed/literal query stratum. This calibration determines whether shorter printed arithmetic offers a reliable regime; its results do not automatically trigger interventions.

## Capture

Use the same pinned cached Llama8B and CodeLlama34B revisions as the original suite. Capture the same four decoder layers. Readout layers are fixed to the original nominated layers24/36, without reference to the new DEV. Extract definition-end, left-use and right-use states and the final answer-preparation state. Definitions are the full assignment's last token; when that is the same token as its right operand, the two roles deliberately share a vector. Every span maps its last character to an exact native token and must expose no future non-whitespace code. An operand's candidates include only definitions strictly before its assignment. Store at most23 points with explicit point counts and zero unused padding, fixed capture batch16 and atomic checksummed32-row chunks. The backbone prefill uses left padding, explicit position IDs, SDPA, BF16 and no generation/KV cache. Saved features are float32 copies of the selected BF16 states. Equal causal prefixes are checked only within matching actual batch geometry.

Native layout preparation and frozen software validation precede collection. All attempts, including interrupted work, retain job IDs, attempted/returned prefills or answers, wall time and GPU telemetry. Completed chunks and behavior batches are immutable and resumable. The loader uses the audited cached-model memory checks with the new batch size and actual prompt length. No language-model weights are trained.

## Shared dependency readouts

Predict the actual read-time parent for each operand. One scorer is shared across every operand position and statement. Statement nodes, candidate boundaries and left/right identity are supplied; this is not arbitrary graph discovery. Compare three feature backends: operand-local hidden state paired with candidate-definition hidden states; global answer-preparation hidden state paired with the same candidates; and character3–5-gram hashes of the exact visible source prefixes. Both hidden backends use a fixed, seed-specific random sign projection to64 dimensions; the source hashes have width64. Each query/candidate vector adds16 supplied position/role coordinates. The global backend receives statement and operand-side identity through those coordinates.

Compare a linear concatenation scorer, a learned rank16 bilinear scorer with unary terms, and a width32 tanh MLP. Linear concatenation cannot express query-candidate compatibility; this limitation is explicit. Each architecture is trained on CPU with AdamW, learning rate0.01, weight decay0.001,25 epochs, minibatches512 and family-balanced exponential weighting seeds11/29/47. Normalization is fitted inside each TRAIN fit partition. Select architecture separately for each backend by mean family-macro parent accuracy across three stratified structural TRAIN folds and all three seeds; ties prefer linear, then bilinear, then MLP. Save all81 CV records and lock selections before reporting DEV results.

For each selected architecture, refit real and random-family control tasks under all three seeds. Random parent labels are valid earlier candidates, stable for each structural family/operand and independent of semantic labels. Match source and random controls to the selected architecture's capacity. Publish complete learning curves with54,108 and216 TRAIN families, selected as nested, fixed-seed balanced subsets of the nine strata. Fit normalization, weights and readouts separately at each size; never select the best curve point on DEV. There are54 post-selection fits per model (three backends × three structure counts × real/control × three seeds), in addition to81 CV fits. Save model weights, normalizers and predictions; reloading must replay scores exactly. Keep per-edge, family-macro, whole-program-graph and depth/side metrics separate.

An exact source-name/most-recent-definition algorithm solves these syntactic parent labels at100%; verify that ceiling for every example. A hidden readout success establishes accessibility under this supplied scaffold, not superiority to all source algorithms, maintenance of an entire global state, functional causal influence, or natural use by the model. More expressive decoders and random projections also change the accessibility question. Preserve the original global linear negative result.

## Execution and recovery

The durable supervisor checks about every ten minutes, installs successors before acting, and retries only resumable scheduler interruptions. Repeated interruptions with no committed progress stop retries; scientific, format and memory failures require review. CPU readouts become eligible as soon as their capture is complete, allowing overlap with other GPU work; actual scheduler QoS determines available capacity. Existing jobs outside the suite are never canceled. Automatic experiment logging continues for source manifests, completion receipts, results and reviews.

The first archived-feature selector completed all CV banks but was blocked at model publication because its output prefix matched the reserved-outcome guard. Preserve that failed version and its selections. The repaired version uses allowed publication names and reuses all CV banks only after checking every payload hash, exact original configuration/source, identical upstream target/feature modules and AST equality of the entire selection runner after removing only the cache adapter and normalizing the output-name repair. Reuse changes output location and adds a pinned cache reference; it changes no selections, folds, features, targets, weights or fits.
