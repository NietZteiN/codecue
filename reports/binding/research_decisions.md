## Generator and matching

Algorithm version 5 generates four scalar chains in every cell. Output relevance is 2 versus 4 variables, verified by liveness; one-variable arithmetic controls preserve the assignment body. The designated variable has exactly 1 or 3 reassignments after its initial computed assignment. Parallel chains, saved snapshots, and interleaved accumulators have explicit generator-defined roles. Snapshot copy destinations are renamed according to their actual role, including in binding-swap controls.

Initial values are computed expressions. Every accepted primary program has at least one computed intermediate absent from its literal tokens. Before rejection, one and three target updates have the same sampled net-displacement distribution; the three-update condition includes cancelling intermediate updates. The output uses `v0 - (v1 + v1)` so snapshots do not reduce to just a net increment. Low/high load and arithmetic controls have four output operations. All accepted live assignment values stay in [-64,64]. Outputs in the primary set are stratified into absolute-magnitude bins 0–5, 6–10, and 11–15, equally across cells, with actual rejection rates and value distributions recorded. These bins match a coarse distribution, not every individual answer. An initial 17–24 bin forced near-extreme snapshot cases and yielded 96.9% rejection. Before any model outcomes, bins were revised to 0–5/6–10/11–15; the final pilot rejection rate is 80.44% (2,467 rejected proposals out of 3,067). Accepted distributions, rather than the proposal distribution, are the study population.

Load is changed by changing the output's relevant inputs while keeping four computed chains. Thus low-load extra branches are genuine irrelevant-code controls. This is a specific operationalization of output relevance, not a claim about model registers. The query arrives last, so identical assignment prefixes cannot differ in their activations solely because their later queries differ. This load factor can affect query-dependent reconstruction or answering; it does not demonstrate different prefix memory load. An early-query or variable-count manipulation would be a separate development sensitivity study. Update count changes program depth and, especially for accumulators, arithmetic work. Those differences are measured and remain a limitation on interpreting interactions as a pure reassignment effect. A subsequent matched depth/operation sensitivity study is needed before such a claim.

Names describe output signs for parallel/accumulator chains, and current/saved roles for snapshots. Misleading names exchange those roles, without changing executed semantics. A query-only role-permutation alternative is included to audit a cheap name-based explanation. It can predict wrong answers without any internal tracking failure. Token lengths, total prompt/source counts, identifier occurrence lengths, positions, dependency depth, assignment distance and operation counts are recorded. Candidate name pools were screened in definition and use contexts with the pinned CodeLlama tokenizer. The completed audit finds exact prompt-token-count equality for both naming contrasts, across all 3,600 primary renderings (1,200 paired lexical comparisons per contrast). Each identifier occurrence was also audited. This is tokenizer-specific and must be rechecked for another model. No regression is offered as a substitute for correcting avoidable mismatches.

Each base has six naming renderings. The pilot contains 600 primary bases / 3,600 primary renderings. Computed binding swaps and one-variable arithmetic controls add 7,200 control renderings, reported separately (10,800 records total). Swaps change ownership of computed values while keeping the final value multiset, including multiplicity. They retain a noncommutative query. Labels include full downstream counterfactual states; a syntactic def-use edge alone is not treated as functional influence.

## Measurement choices

Behavior uses a pinned CodeLlama chat template, greedy short answers and a strict signed-integer parser. Raw outputs and invalid responses remain separate from parsed semantic errors. Matching diagnostic alternatives produce a set of compatible labels, including no-effect and colliding alternatives; they never prove an internal cause. The inference unit is a parent structural template. Bootstrap intervals, paired naming effects and naming-by-load/update contrasts are descriptive discovery summaries, not a multiplicity-corrected confirmatory analysis.

Extraction uses raw zero-based decoder block outputs at the last token of each assignment and the final output-expression token. Offsets are resolved separately for every rendering. Tokens crossing a checkpoint boundary are refused. Labels refer only to assignments preceding that checkpoint. The two probe curves compare the last assignment with the final source position, which reveals the query; they are not interchangeable memory measurements.

Primary decoders are four-output ridge regressions with integer rounding and fixed alpha=1; parameter counts and train-only standardization are reported. Current values, designated previous versions and sorted multisets have separate fits with the same output capacity. Baselines are training-label modes/priors, hashed surface-token features, and three base-keyed randomized-label tasks sampled from training label distributions. Within-condition fits and neutral-to-transformed transfers are reported on development only, across all supplied layers/sites. This does not establish natural use, information absence after failed decoding, or a learned slot implementation. No best layer has been selected.

The intervention command is a development value-transfer assay with one predeclared block, computed donors and no-op, self, wrong-variable, obsolete-version, same-answer/different-state, shuffled, matched-norm and reciprocal controls. Full-residual replacement can steer answers broadly. The continuation adds late quantity queries for dependent/independent diagnostics, and an executable ownership-matched donor mode. Relevant/irrelevant path specificity and convincing ownership effects are still required for M4; a successful value assay alone does not pass that milestone.
