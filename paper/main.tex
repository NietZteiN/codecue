\title{Misleading Identifiers Change What Code Traces Write}

\author{Anonymous ACL submission}

\begin{document}
\maketitle

\begin{abstract}
Language models can write an incorrect intermediate value in a code trace even when
the correct value is recoverable from their internal activations. Extending
\citeauthor{kudo2026faithful}'s arithmetic analysis to code, we evaluate \NUM{n-models}
models on matched Python programs that differ only in a variable name. When a variable
holds a list's length but its name suggests a sum, three models write the sum more often
than under ordinary names. On these incorrect traces, linear predictors trained on
separate programs recover the correct digit with \NUM{crossfit-min}--\NUM{crossfit-max}\%
accuracy immediately before the model writes the wrong value. Worked examples that show
the operation alongside its result sharply reduce these errors; equally long descriptive
annotations leave large effects. These findings distinguish values recoverable inside a
model from those reported in its trace, and show that demonstrating the operation helps
the written trace follow the program despite a misleading name.
\end{abstract}

\section{Introduction}

A variable named \texttt{sum\_all} is assigned \texttt{len(xs)}. For \texttt{[5, 3]}, its
value is 2, regardless of its name. Suppose a language model is asked to trace the program:
write each assignment's value, then the return value. In Figure~\ref{fig:idea}, OLMo-2-7B
writes 8 for this variable, following the sum suggested by the name. We call this a
\emph{name error}.

Changing only the worked examples changes this trace. When examples show values alone,
the model writes 8. When they also show the operation used to obtain each value,
it writes 2. The program, input and model are unchanged.
This contrast motivates our study: how do variable names and the format of worked examples
affect which value a model writes?

\centering

under demonstrations showing values alone (red) or expressions with values (green).}
\label{fig:idea}
\end{figure*}

Earlier work shows that misleading identifiers reduce code accuracy
\cite{le2025names,lam2025codecrash,le2026obfuscated}. The wrong trace raises a further question:
when the model writes 8, can we still recover 2 from its internal activations? We build on
\citet{kudo2026faithful}'s analysis of intermediate values during arithmetic reasoning.
Their probes test what values can be recovered from activations; their patching experiments
replace activations to test how outputs change. We apply these tools to code with a
deliberate conflict between a variable's assigned operation and its name.

We train a \emph{linear probe}, a small predictor of the true digit, on separate programs.
It reads activations immediately before the model writes a value. We show that this
predictor usually returns the computed digit even when the trace follows the misleading
name. Showing the operation in worked examples sharply reduces those wrong writes;
extra descriptive text of the same length leaves large effects. The worked examples
therefore change whether the trace writes the value computed by the code or the value
suggested by the name.

\section{Study design}

Each problem is a short Python function over a list of distinct digits. Assignments apply
list aggregates (\texttt{len}, \texttt{sum}, \texttt{max}, \texttt{min}) or integer operations,
followed by a return and a call. True intermediate and final values are single digits.
The main level has three dependent assignments; Appendix~\ref{app:levels} gives the full design.
We test \NUM{n-models} instruction-tuned models with 1,000 matched problems per level and target,
with three fixed sets of three worked examples. CodeLlama-34B supplies an additional scale check.

Each matched pair differs only in one target identifier. A congruent name implies the assigned operation;
a misleading name implies another. Its name-suggested value must differ from every value, constant and
input element in the problem. This prevents copying from explaining a name error and excludes \texttt{max} and \texttt{min}
as name-suggested operations on the aggregate step. We also check which operation each model associates
with each identifier. The original main names fail the planned 80\% panel gate, a selection-rule
deviation. We disclose it and independently replicate with screened names and fresh programs
(Appendix~\ref{app:round6-identifiers}).

In the \emph{direct} regime, models write the return value. In \emph{trace}, they first write
each assignment's value, as in \texttt{qq = 3, v = 6, vv = 9}. The \emph{trace-expr} comparison
adds the expression to each demonstrated step, as in \texttt{qq = len(xs) = 3}.
REPL, comment and free-prose formats test the effect's scope (Appendix~\ref{app:formats}).

Our main measure is \emph{excess name errors}: the rate at which a misleading trace writes
the name-suggested value at the target step, minus the neutral twin's rate of writing that same digit.
We measure name errors similarly in the direct regime. We call an effect reliable when its sign
agrees across all three demonstration sets and a 95\% cluster-bootstrap interval excludes
zero. To support a small-effect claim, a 90\% interval must fit inside the preregistered
$\pm\NUM{eq-delta}$-point margin. Other cases remain inconclusive
(Appendix~\ref{app:stats}).

For three models, a linear probe predicts the target digit from a hidden state at one token
and layer. Training uses disjoint computations and three probe seeds; layers are selected
on neutral programs in other folds before each held-out computation is evaluated.
We read the \emph{decision token}: the \texttt{=} immediately before the first traced value.
The generated and cached token prefixes must agree through that token; no value digit is
included. Patching replaces the name tokens or this position with a matched neutral twin's
activations. A neutral-for-neutral patch measures disruption. Controls and implementation
details are in Appendix~\ref{app:probes}.

\section{Results}

\subsection{Terse traces follow a misleading name}

Table~\ref{tab:cells} shows the main level. Under sum-like names, length-computed variables
produce \NUM{cell-olmo7-excess}, \NUM{cell-llama3-excess} and \NUM{cell-llama8-excess} points
of excess name errors in OLMo-2-7B, Llama-3.2-3B and Llama-3.1-8B. On neutral programs, their trace accuracies are \NUM{cell-olmo7-acc}, \NUM{cell-llama3-acc} and \NUM{cell-llama8-acc}\%,
respectively. These models usually trace neutral programs correctly.

The sum is not these models' usual error on a length step. On wrong neutral traces, sum writes
account for only \NUM{neuerr-sum-lo}--\NUM{neuerr-sum-hi}\% of errors; maximum values and
off-by-one lengths are more common. The sum-like name changes which wrong value they write.
CodeLlama-7B's larger effect occurs on a maximum-computed variable
(\NUM{cellmax-codellama-excess} points); CodeGemma-7B shows that pairing at level~3.
The full pairing matrix is in Appendix~\ref{app:matrix}. Direct-answer name-error effects are much
smaller: \NUM{direct-lure-min-L5} to \NUM{direct-lure-max-L5} points at this level.



\subsection{The correct digit is decodable on error cases}

On generations that write the name-suggested value, neutral-trained probes recover the computed digit with
\NUM{crossfit-olmo7-accuracy}\%, \NUM{crossfit-llama3-accuracy}\% and
\NUM{crossfit-llama8-accuracy}\% accuracy in OLMo-2-7B, Llama-3.2-3B and Llama-3.1-8B.
The prefixes match through the decision token in all \NUM{errorprobe-prefix-n} generations
across the three demonstration sets. The cached state therefore also precedes the model's
actual value write. Appendix~\ref{app:round6-probes} reports clustered intervals and the
correct-write and other-error strata.

Five-fold layer selection excludes each test computation. Neutral name-identity controls
score \NUM{probe-olmo7-ctl}, \NUM{probe-llama3-ctl} and \NUM{probe-llama8-ctl}.
Recovering the correct digit on an error establishes decodability, not its use in generation.

Patching independently tests sensitivity to the name and the writing position
(Figure~\ref{fig:mechanism}). Replacing name tokens at layer~0 removes
\NUM{patch-olmo7-name-best}\% and \NUM{patch-llama3-name-best}\% of name errors in the two
models with aligned twins. Name-site removal declines in later layers. At the decision token,
removal is weak early and strong from the middle of the network onward; all-layer replacement
removes \NUM{patch-olmo7-pre-all}--\NUM{patch-llama8-pre-all}\%. The neutral-word control
changes at most \NUM{patch-llama3-wordctl}\% of outputs. The patches identify positions sensitive to the misleading name. They replace an entire
hidden-state vector, so they cannot identify which feature changes the output.

\subsection{Showing the expression reduces the effect}

We keep the programs, models and demonstration sets fixed and change the examples from
\texttt{v = 3} to \texttt{v = len(xs) = 3}. Name-error rates fall by
\NUM{expr-olmo7-drop}, \NUM{expr-llama3-drop} and \NUM{expr-llama8-drop} points in the three
models (Table~\ref{tab:formats}). OLMo-2-7B retains
\NUM{cell-olmo7-traceexpr-excess} points of excess; the two Llama effects approach zero.
Length-matched neutral annotations leave \NUM{format-olmo7-annotation-mean} and
\NUM{format-llama3-annotation-mean} points of excess in OLMo and Llama-3.2. Valid numeric
elaborations (\texttt{v = 3 + 0 = 3}) lower it to \NUM{format-olmo7-numeric-mean} and
\NUM{format-llama3-numeric-mean} points, still above source-expression demonstrations
(Appendix~\ref{app:round5-formats}). Extra tokens do not reproduce the expression benefit;
adding arithmetic accounts for part of it.

With \NUM{r6-name-n} independently screened names on \NUM{r6-program-n} fresh computations,
trace excess in OLMo-2-7B, Llama-3.2-3B and Llama-3.1-8B is
\NUM{r6-olmo7-trace-mean}, \NUM{r6-llama3-trace-mean} and
\NUM{r6-llama8-trace-mean} points; expression excess is \NUM{r6-olmo7-expression-mean},
\NUM{r6-llama3-expression-mean} and \NUM{r6-llama8-expression-mean}.
CodeGemma shows no observed excess in either format (Appendix~\ref{app:round6-identifiers}).

\section{Related work}

Misleading identifiers affect real-code accuracy
\cite{le2025names,lam2025codecrash,le2026obfuscated,orvalho2025mutations,gao2023cream}.
Our synthetic tasks separate computed and name-suggested values.
\citet{kudo2026faithful} study arithmetic readouts; \citet{anon2026arith} find their association
with arithmetic name errors sensitive to task competence. Neither establishes a mechanism
shared with code traces. Faithfulness studies perturb prompts and chains
\cite{turpin2023unfaithful,lanham2023measuring,chen2025reasoning}; we intervene at the
value-writing position. Stroop studies focus on next-token prediction
\cite{stroop1935,geirhos2019texture,wang2026stroop,hu2026conflict}.

\section{Conclusion}

Terse code traces can write a name-implied value while the computed digit remains decodable.
Patches and expression demonstrations reduce these errors; the format contrast replicates
with independently screened names. Length-matched annotations leave
large effects, while numeric elaboration helps partly. The finding concerns the tested names
and formats; it does not establish a general failure of code computation.

\section*{Limitations}

\begin{itemize}
\item \textbf{Scope.} Programs are synthetic with single-digit values; the largest effect
uses a constructed trace format. REPL and comments show smaller effects. The
\NUM{crux-n}-function CRUXEval check bounds direct-answer and prose accuracy, not synthetic
trace errors. Models reach 34B; the panel excludes Chinese-origin models, including strong
code models in \citet{le2026obfuscated}.
\item \textbf{Internal measurements.} Probes on three smaller models establish decodability,
not use. Error readouts select layers independently; full-neutral curves and name controls
are descriptive. Patches replace mixed representations and may have side effects.
Llama-3.1-8B's \texttt{sum\_all} lacks an aligned twin for name-site patching.
\item \textbf{Design deviations.} The registered REPL prediction failed. All three main-cell
names fail the planned panel meaning gate, leaving its filtered estimate unavailable.
Screened-name replication supports the format contrast but does not repair that deviation;
probes and patches retain the original names (Appendix~\ref{app:round6-identifiers}).
\end{itemize}

\section{Identifier meanings}
\label{app:gate}
For each identifier and model, we compare log-probabilities of candidate right-hand sides after
a prefix such as \texttt{def f(xs):\textbackslash n\ \ \ \ total =}.
The highest-scoring operation records what that identifier evokes. Of \NUM{gate-names} names,
\NUM{gate-pass} match the intended operation in at least 80\% of models. Most sum-family names
instead evoke length in \NUM{gate-sum-len-readers} of \NUM{n-models} models. This check matters
when interpreting a small effect: an identifier need not suggest the same operation to every model.
The design planned to retain only names passing the 80\% panel gate. The runs instead retained
the full name table, so the reported comparisons depart from that selection rule. The results
concern these named groups; they do not establish that every model reads each name as intended.

\section{Probe and patching details}
\label{app:probes}

We follow \citeauthor{kudo2026faithful}'s 10-class linear-probe recipe, with three seeds and
neutral-only training. Each probe predicts a target digit from one residual-stream position
and layer. Name-identity controls use deterministic random labels keyed on the identifier
\cite{hewitt2019control}. Neutral names and values vary independently, and misleading names
are absent from training. The original implementation reused test programs in training. The reported reruns
replace those scores: they train on \NUM{probe-n-train} independent neutral programs and
evaluate \NUM{probe-n-test} misleading-name programs, with overlap guards that ignore name
spelling. Table~\ref{tab:probe-repeats} reports the name controls alongside digit accuracy.

% Disjoint-probe demonstration repeats
The main scores use demonstration set 7. Repeating training and evaluation with sets 11 and 13
gives true-digit accuracies of \NUM{probe-olmo7-demo-lo}--\NUM{probe-olmo7-demo-hi}\%,
\NUM{probe-llama3-demo-lo}--\NUM{probe-llama3-demo-hi}\% and
\NUM{probe-llama8-demo-lo}--\NUM{probe-llama8-demo-hi}\% across the three sets. Each repeat
uses the same independent training programs and three probe seeds; its layer is selected by
that set's neutral accuracy. These repeats assess prompt sensitivity, not a causal role for
the decoded digit. Table~\ref{tab:probe-repeats} gives both conditions' readouts and controls.

every sum-family identifier implies the same sum, so there is no distinct source name-suggested value.
Llama-3.1-8B's affected two-token name lacks aligned neutral twins for the name-site intervention.

\section{Scope checks}
\label{app:boundaries}

\paragraph{Operation and scale.} Moving the misleading name to a unary middle step produces
no reliable effect for models above the accuracy floor; the largest excess is
\NUM{l6-max-excess} points. CodeLlama-34B's length-to-sum effect is \NUM{cell34-len-excess},
while its maximum-to-sum effect is \NUM{cell34-max-excess} points
[\NUM{cell34-max-lo}, \NUM{cell34-max-hi}]. The latter is a reliable positive effect, but its
interval extends beyond the two-point margin. Its small point estimate cannot be reported as
equivalence. The larger-checkpoint result supports the registered maximum-to-sum direction
and reliable-effect criterion, while its magnitude is much smaller than CodeLlama-7B's.

\paragraph{Natural code.} We select \NUM{crux-n} CRUXEval functions with length, loop-counter
or maximum assignments, rename the target by AST rewriting to \texttt{v} or \texttt{total},
and verify execution after renaming. Direct and prose accuracy contrasts all have intervals
covering zero on the \NUM{crux-used} functions whose renamed target is used downstream.
Their endpoints stay within \NUM{crux-direct-bound} and
\NUM{crux-prose-bound} points, respectively (Table~\ref{tab:crux}). These are bounded results
for those functions and prompts; they do not test the terse few-shot trace used in the synthetic
study.

\section{Effect and equivalence checks}
\label{app:stats}
Each contrast subtracts the neutral twin's rate for the same digit. We resample matched problems
with demonstration-seed replicates together and use 95\% cluster-bootstrap intervals.
Reliability also requires a consistent sign across all three demonstration sets.

Equivalence applies the $\pm\NUM{eq-delta}$-point margin to 90\% intervals from the same
cluster bootstrap (two one-sided 5\% tests), using 2,000 draws. Across \NUM{eq-cells} tested contrasts,
\NUM{eq-equivalent} intervals lie wholly inside the margin, \NUM{eq-witheffect} contrasts have
reliable effects without meeting that bound, and \NUM{eq-inconclusive} meet neither criterion.
A small estimate or an interval covering zero does not by itself establish equivalence.
