## Formal sources and interventions

Four integer root variables are followed by the nontrivial prefix. Numeric generation uses seeds **20261101/20261102/20261103**, separate from future fitting seeds **11/29/47**. Sample roots from −6 through 6; reject states exceeding the existing ±96 live-value domain. Ensure the second operand is nonzero so the binding swap has a functional output contrast. Choose a mutation constant from −12 through 12 that differs from the first operand's value. Record numerical support and failed search limits; no model outcomes inform generation.

The retention pair assigns `v2 = v0 + v1` or `v2 = v0 - v1`, then writes the same constant either to operand `v0` or irrelevant slot `v3`. The correct retained `v2` is unchanged. Recomputing from the updated operand produces a distinct wrong value in the operand condition. Vary the retention delay over **0/4/12** identity assignments to `v3`. Finish with `v2 = v2` as a later use; its read-time parent is the earlier version, while its destination creates a new version with the same value. Preserve both labels. The four-value output changes at the deliberately mutated slot; only the retained target is invariant across mutation conditions.

A separate binding pair assigns the sum and difference of the two computed operands to `v2` and `v3`, then swaps the destinations. Both programs have the **same Python lexical-token multiset and final current-value multiset**, but different correct `v2` answers with fixed query text. Delays and later self-use preserve that value multiset. The guarantee applies after both paired writes, at later use and final query; the target-write checkpoints occur at different write positions and are not labeled as bag-matched. Native wordpiece multisets need not match. Both assigned values are arithmetic results; introducing a literal target would collapse the live ancestry and is avoided in the formal bank.

Every formal family has 12 retention variants and six binding variants per numeric seed and realization. Include two neutral lexical maps and two root initialization orders. This yields **27,648 formal source rows**, plus **216 calibration rows**. Validate all four realizations using the restricted versioned interpreter and independent ordinary Python execution of every assignment. Check retention-pair source matching, unchanged retained values, functional recomputation alternatives, binding token/value multisets, root-order/renaming equivalence, complete delay factorials and cross-split canonical closure. Keep coincident error labels and report their counts; an answer matching an error candidate alone does not establish that internal mechanism.

Calibration contains literal, copy and one-/two-/three-operation arithmetic sources, including finite prefix/control variants, three numeric seeds and all delays. Merge equivalent calibration templates; do not count nominal template tags as independent families. None are used for probe fitting.

## Model inputs, query scopes and native temporal sites

The primary native bank uses lexical map 0 / root order 0 for the formal sources. Other nuisance realizations are execution-validated and retained as a sensitivity bank; their inference is deferred. For each primary source, preflight both query scopes—`print(v2)` and `print(v0, v1, v2, v3)`—and all three output-only instruction variants. All-variable outputs use an ordered bracketed list in print argument order. A separate tested parser accepts four signed integers; the single-output parser accepts one. Parse the last `Answer:` line and retain malformed outputs.

Calibration additionally preflights explicit intermediate-query and model-generated stepwise instructions. Query and instruction suffixes appear **after the code body**, so earlier causal token prefixes are matched by construction and verified natively. No oracle trace, true intermediate, assignment version, split ID or gold answer appears in model inputs. Explicit intermediate instructions request a variable/line from the visible source, without supplying its value.

Use the cached, revision-pinned Llama 3.1 8B and CodeLlama 34B native fast tokenizers, with the existing audited CodeLlama boundary correction. Load tokenizers only in CPU SLURM allocations. For every prepared case, verify offsets and exact decoded causal prefixes at RHS end, assignment newline and later use. Require identical earlier prefix hashes across scopes, wording variants and protocols. Record unavailable sites when a native token exposes future non-whitespace source. At least 95% of RHS and later-use sites must be available; preserve all unavailable records rather than dropping cases. RHS/newline positions that coincide are explicitly collapsed and cannot count as separate temporal evidence.

Output-only prompts append an assistant `Answer:` prefix and have a pre-answer boundary. Intermediate/stepwise prompts have a **pre-trace-generation** boundary, not a pre-answer state. Later answer-state capture requires a generated-trace implementation and visibility flags before any claim. Never teacher-force a gold intermediate. Preserve whether the target is already a source literal, including signed literal identity rather than digit substring matches.

Per model, the native bank contains **41,472 formal output-only layouts** and **3,888 calibration layouts**. Exact native prompt duplicates fail preflight rather than repeat deterministic inference. Prepared token streams, site masks and complete prompt identities are hash-pinned on scratch.

## GPU calibration and feasibility gates

Both native preflights must pass before either calibration job runs. Use only the **1,296 delay-zero calibration prompts per model**, covering all numeric seeds, instruction variants, scopes and protocols. No formal TRAIN/DEV prompt is inferred. Reuse audited cached BF16/SDPA loaders with no checkpoint downloads or training. Greedy generation uses batches **128 for 8B / 64 for 34B**, with worst-case KV-cache and working-memory checks before generation. If the declared batch does not fit, fail for review; do not alter the cohort or protocol silently.

Maximum new tokens are **64 output-only / 128 intermediate-query / 512 stepwise**. Record all returned token IDs, raw responses, EOS/truncation, ordered per-slot scores, attempted/returned/committed counts and source identities. Invalid or truncated responses remain in every accuracy denominator. Successful exact batches are immutable and resumed without duplicate model calls; preserve attempt metadata on interruptions. Calibration is not a probe fit.

On depth-zero, output-only calibration, each instruction variant and each scope separately needs literal joint accuracy ≥95%, copy ≥90%, and one-hop arithmetic ≥70%. These finite feasibility thresholds are not significance tests or model-capability estimates. All wordings remain in the report; no best wording is selected. Intermediate/stepwise results are separate diagnostics. A failed competence gate is a scientific outcome, not a reason to hide responses. Any revised protocol preserves this pilot and is frozen in a new edition before formal collection. Passing does not automatically launch formal inference in this suite.
