# Computed retention-frontier discovery

This study addresses the relevant-live-variable gap in the [research backlog](research_backlog.md). Earlier arithmetic-free available-variable counts included irrelevant competitors. Here, the execution oracle verifies exactly 2, 3 or 4 bindings whose current values can affect the final output across an irrelevant block.

The program computes `r = a - b`, `s = c - d`, then `r - s`. Move zero, one or both independent computations before eight dead assignments (`buffer = spare; buffer = 0`, repeated four times). With both computations early, only r/s remain output-relevant across the block; with neither early, a/b/c/d remain relevant; one early computation leaves three relevant bindings. Both computation orders are included. Both result slots are initialized in every program, so all eight variables are defined at each retention checkpoint even though only 2, 3 or 4 are live. A control without the dead block uses one unique prompt per order, shared as the clean anchor rather than evaluated redundantly for every logical frontier.

Every scheduling contrast preserves the complete final state, expected answer, all three subtractions, statement multiset, numeric literal exposure and full prompt token multiset/length. The assignment-history factor redirects two old assignments to the relevant input a or a dead buffer, giving one versus three reassignments of a at fixed literal exposure, final state and statement count. All three naming conditions and two lexical realizations are included; misleading names swap the two result-role identifiers. Informative/misleading prompt lengths and low/high reassignment lengths must match. Neutral names may have different token lengths and are reported separately.

This is a **computation-scheduling/retention-frontier manipulation**. It necessarily changes when subtractions occur, the ages of live definitions and their distances from the query. Those token distances are recorded and reported. Oracle liveness is a property of the program, not evidence that the transformer stores that number of registers or must follow the program's execution strategy. The behavioral contrast alone cannot isolate a memory-capacity effect.

The numeric bank has 384 states in 192 sign-reversed pairs, distributed over 24 initialization-order structural components. The four current inputs are distinct; computed intermediate/output magnitudes do not occur as integer literal values anywhere in the program. This does not guarantee that every digit subtoken is absent. Obsolete values can coincide with other inputs, and compatible error labels retain ambiguities. Each pair has the same input-value multiset and opposite answer; zero answers are excluded by the fixed semantic design, without observing model results.

All naming, scheduling, update, order and numeric relatives stay within a structural split. The resulting main bank contains 36,864 prompts, with 18 training and six development components. No language model is fitted on these splits. Add 384 direct-literal arithmetic controls and 768 decomposed arithmetic controls, explicitly marked calibration; their structures and matched numeric states do not establish held-out generalization. Total: **38,016 prompts per model**, 76,032 across the two preselected cached checkpoints, Llama 3.1 8B Instruct and CodeLlama 34B Instruct. Existing `print_direct_v3` protocols and audited tokenizer boundaries are fixed; there is no response-based prompt/model selection.

The semantic audit independently executes every rendered program and the full traces of canonical checkpoint counterfactuals. Counterfactuals insert a replacement **at the checkpoint**, preserving already-computed results. Replacing an earlier defining assignment and recomputing completed ancestors would test a different question. Every currently live variable must affect the output under its checkpoint perturbation, and every currently dead variable must leave it unchanged.

All behavioral results are collected regardless of reliability. A fixed descriptive gate requires at least 90% accuracy, at most 5% invalid outputs and at least 24 examples in each direct/decomposed arithmetic calibration cell and each neutral clean-program split × update × computation-order cell. Only a complete pass qualifies the regime as a candidate for later mechanistic follow-up. This does not override any historical failed gate or open old final outcomes.

The two predeclared primary exploratory contrasts are `live4_minus_live2:neutral:updates3` and `naming_by_load_by_updates`. Report the entire fixed matrix as well: 3-versus-2 and 4-versus-2 live-binding comparisons, noise-minus-clean effects, update contrasts, misleading-minus-informative contrasts and naming/load/update interactions. Shared clean anchors are explicit. Intervals resample whole structural components using 2,000 draws with seed 907; they are exploratory, without multiplicity-adjusted confirmatory claims. Initialization orders and deterministic responses are not independent model/family replications.

The active generation configuration is `configs/binding/competition/live_load_generation_v2.json`. Version 1 was retired before any model inference because the number of defined variables differed across frontiers; its data, source, CPU audits and canceled job chain are preserved. The native Llama tokenizer also required allowing trailing whitespace within a statement-ending token; tokens including later code remain prohibited. Separate model configurations, frozen source, tokenizer proofs, job IDs, runtime telemetry, all responses and audits are recorded under `artifacts/binding/live_load/`. Only cached checkpoints are used. Compute accounting is uncapped; allocation requests and memory adaptation follow actual scheduler/hardware constraints. No new activation bank, model training, optional extension or final-test forecast is launched by this study.

Completion status: all 76,032 main predictions, audits, individual reviews and combined reports are complete. Both fixed reliability gates failed. Corrected independent backend/cache checks are complete after fixing a diagnostic prompt/completion stop-boundary error. All 247 tests pass.
