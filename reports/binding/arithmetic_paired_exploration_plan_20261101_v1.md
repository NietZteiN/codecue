# Calibration exploration and next experimental branches

November 1, 2026. Exploratory follow-up to the completed paired calibration. The pilot used 64/128/512 generated-token ceilings for output-only/intermediate/stepwise respectively. Both checkpoints failed its frozen output-only competence gates. Raw examples expose genuine arithmetic errors, explicit Markdown answer headings rejected by the strict parser, and truncation both before and after an answer. These observations motivate the assays below; they do not license changing the original scores.

## Executed in this edition

1. **Independent scoring and error audit, no new model queries.** Join all 1,296 calibration responses per model to the hash-pinned native prompts and source oracles. Reconstruct strict acceptance, per-slot correctness and joint accuracy using a separate regex implementation, then replay the original full scorer and summary. Require complete unique prompt identities and calibration-only delay-zero scope. Report every protocol/scope and every task/depth/instruction/mutation cell with structural component counts. Compare single and all-variable prompts on the SAME retained target, keeping all invalid outputs in denominators. No wording selection, confidence intervals or significance claims on these correlated finite templates.

2. **Target-blind formatting sensitivity.** Preserve the last explicit answer label. A separate diagnostic grammar also admits Markdown headings such as `**Answer:** -3` and `**Final Answer:**` followed by a value on the next line. Require one signed integer or exactly four ordered bracketed integers. A later malformed label invalidates an earlier answer. Never search for expected numbers, choose a correct candidate, mine unlabeled trace numbers or interpret arbitrary prose. Completed-response diagnostic accuracy still treats every truncated output as a failure. Separately count strict correct answers that appeared before truncation; this is answer availability, not official accuracy or a gate revision.

3. **Prefix-preserving length continuation.** For BOTH cached checkpoints, continue EVERY and ONLY truncated pilot response, regardless of correctness, task, wording or scope. Reuse all completed EOS responses exactly. Append to the original native input IDs and saved generated token IDs without decode/re-tokenization. Greedy continuation has a common **1,024 total generated-token ceiling**, including the pilot prefix. This is a length sensitivity contrast on fixed generated prefixes, not a monolithic rerun or an isolated effect of reasoning. Preserve the pilot prompt, suffix, forced assistant prefix and all labels. Generation batches are fixed at 64 for Llama8B and32 for CodeLlama34B; validate native prompt tokens, saved text/token decoding, EOS absence, checkpoint geometry/backend and memory before inference. No silent batch/cohort reduction. Original and continued scores remain separate. A longer limit is an experimental condition, not a cumulative compute allowance.

4. **Descriptive error candidates.** Retain all matches to stale target, recomputed current operands, opposite operator and another current binding. Restrict wrong-target summaries to predictions differing from the true target; preserve collisions. These are value coincidences and possible explanations, not identified internal mechanisms. Keep full raw text/token IDs, component IDs and source joins for review.

Full frozen binding regression gates the audit; the audit gates both GPU continuation jobs. The intermediate audit report can finish before GPU results. Final reporting is gated on both continuation completions. Scratch-first immutable batches resume without repeating committed continuation inference. Durable ten-minute monitors retry scheduler interruptions and stop scientific errors. Actual scheduler constraints apply; GPU usage is accounting-only. No formal TRAIN/DEV inference, probe fitting, optional backbone training, causal interventions or sealed-final access in this edition. Literature review and register remain hash-pinned.

## Additional exploratory branches, prepared as decisions rather than launched claims

| Question | Experiment | Informative contrast | Condition before launch |
|---|---|---|---|
| Was a value computed but then lost? | Paired RHS/newline/overwrite/delay/later-use hidden capture | Same target immediately after computation versus after operand/irrelevant mutation and0/4/12 delays | Audited competent protocol; new frozen capture recipe |
| Does asking for more variables change target access? | Matched single/all query scope | Same target and same code, controlling answer validity and avoiding joint-versus-single comparisons | Adequate behavior and explicit pre-answer boundaries |
| Is numeric content present but assigned to the wrong name? | Same-token-bag/same-final-value-bag binding twins | Value bag recovery versus correctly bound slot recovery | Use guaranteed bag-matched later-use/query sites |
| Do hidden states add information beyond textual cues? | TRAIN-selected source-plus-hidden versus source-plus-zero predictors | Conditional predictive gain at matched capacity, grouped folds and coherent shuffled controls | Formal captures and frozen feature/selection protocol |
| Does a shared decoder generalize variable identity? | Shared slot-conditioned value decoder versus independent per-slot heads | Held-out neutral renamings/root orders and full-width versus1024 features | Keep slot pointers and metadata access matched and explicit |
| Can relations be decoded without first decoding exact values? | Direct pair relation heads versus relations derived from predicted values | Equality/order/sum/difference with support/prevalence controls and source comparator | Family-held-out fits; no oracle values in inputs |
| Is information reused across stages? | Cross-site transfer after within-site readouts | Train at computation, test at retention/query versus within-site accuracy | Reliable within-site readouts first |
| Does the decoded information influence answers? | Targeted donor interventions with layout-matched controls | Specific changes in the predicted bound value and downstream behavior | Stable readouts, competent behavior, new causal protocol |

Do not launch a large architecture sweep before locating the failure stage. These branches are competing explanations: computation, retention, binding, query access, response formatting and generation length. Select a small next wave from the audited outcomes, freeze it before collection, and reserve fresh structural families for confirmation of any chosen discovery.
