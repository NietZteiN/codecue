# Literal-value routing discovery assay

This assay follows the completed site/readout measurements. It changes one directly assigned positive digit and patches a raw decoder-block vector into an otherwise unchanged prompt. It tests literal-value routing through ownership swaps and snapshots/overwrites. It cannot establish a general binding register, computed-value transport, or an explanation of the earlier competition errors.

The registered configuration is `configs/binding/competition/value_transfer_v1.json`. The independently checked dataset contains 432 programs: nine cyclic numeric triples, two families, two ownership/overwrite mappings, two neutral lexical realizations, two queries and three literal variants. Every original has one donor for each initial literal. Both transfer directions are retained, giving 576 directed pairs. Exactly half have a changed oracle answer; the other half query the other owner or assignment version and must retain their answer. No case is selected by model accuracy. All data are discovery/development, with two templates per family and no confirmatory holdout claim. Numeric and lexical variants are not independent structural replications.

The pinned Llama 3.1 8B checkpoint and `print_direct_v3` interface are reused. Actual-tokenizer preflight must establish that each pair differs at precisely one positive-digit token and has identical token positions and total length. The unrelated zero-literal position precedes the changed literal. Both complete-program semantic oracles must agree. No tokenizer or checkpoint is loaded outside SLURM.

At each raw block 0, 8, 16, 24 and 31, retain all seven conditions: literal-vector replacement; the same value-change direction added at the unrelated zero literal; full donor answer-prefill vector replacement; identity sham; and three random-direction perturbations at the literal (seeds 11, 29 and 47). Random and unrelated-position perturbations match the literal transfer's effective Euclidean norm **after BF16 rounding**, within the fixed 3% tolerance. Zero perturbations remain exact zero. Direction seeds are sensitivity controls, not experimental replications. A final-block literal patch has no subsequent attention layer through which to affect a later answer; it is a useful boundary control. Answer-prefill vector transfer is an answer-copy software positive control, not binding-mechanism evidence.

All 432 baseline responses are greedily generated and saved with raw text, token IDs, oracle scores and exact prefill-logit/first-generated-token agreement. Earlier literal-site activations must be invariant across future-query relatives with equal token layouts. Direct-forward recipient replays use the intervention batch order, fixed padding width and logical rotary positions. Each patched forward verifies that its actual destination vector exactly equals its same-batch replay. The identity sham must preserve that replay's first token. Baseline-generation/replay differences, if present, remain explicit. Resumable caches carry checksums and frozen source/configuration identities.

The primary measurements are the next-token replacement rate, original-answer retention, and change in replacement-versus-original log odds relative to the unpatched same-batch replay. They are first-token measurements, not complete-output intervention accuracy. Report every layer and condition, separately for ownership and versions and for affected and unchanged-answer queries. Retain both directions, both lexical realizations and both mappings in the data. Report all cases first, with the subset where both complete baseline answers were correct as a secondary descriptive analysis. No layer is selected as a confirmed mechanism; no multiplicity or population-level inference is claimed. A further registered assay would be needed to test computed values, semantic generalization and prediction of held-out failures.

The finite cohort contains 20,160 intervention forwards. Batch size 48 divides the baseline and pair counts and fits the earlier measured memory profile; A30/H100/H200 are eligible. Usage is accounted without a project compute cap. Frozen source, SLURM job IDs, complete output audits and any failed attempts are recorded under `artifacts/binding/value_transfer/`. Generated final and extrapolation outcomes remain sealed; no language-model training is performed.

The completed v1 software run measured a formatting space before the digit. Its digit-transfer rates are not valid answer-transfer measurements. The separately frozen [v2 boundary correction](value_transfer_boundary_correction.md) adds only that fixed space token and requires explicit answer-digit alignment on all baselines. The original pre-inference design is retained in `artifacts/binding/value_transfer/design_before_inference_v1.md`. An isolated post-block token replacement leaves other positions' earlier states intact, so a failed patch cannot establish information absence.
